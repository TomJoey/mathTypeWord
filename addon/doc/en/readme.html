MathType equations in Word

Lets NVDA read and navigate MathType and Equation Editor 3.0 equations in Microsoft Word without MathType's 32-bit DLL. Since NVDA became 64-bit (2026.1) NVDA's own MathType support no longer works (NVDA issue 20115). This add-on reads the equation data from Word, converts it to MathML in pure Python, and lets NVDA's math support (for example MathCAT) speak and navigate it.

Requirements

  • NVDA 2026.1 or later, Microsoft Word (Microsoft 365 / 2016 or later). MathType does not need to be installed.
  • In NVDA settings, Math: turn off "Use native math support in Word and Outlook". When it is on, NVDA disables all math providers while Word has the focus.
  • A math speech provider, for example MathCAT.
  • For the best result the document should be saved as .docx. Equations of a saved document are read from the file, which is much faster than asking Word.

Word object model and UI Automation

Both reading modes are supported. In NVDA settings, Advanced, "Use UI Automation to access Microsoft Word document controls" can be "Only where necessary" or "Always". Changing it applies to newly opened Word windows.

With UI Automation, Word does not give NVDA the equation itself. The add-on matches the equations through Word's object model. A match is only used when it is certain: the text of the range must equal what Word reports, the number of equations must agree and nothing else (pictures, shapes) may be in the range. In every other case the equation is left silent, never read wrongly.

Known limits

  • Only the main text of the document is supported (not text boxes, headers, footnotes).
  • Templates of MathType that were never seen in test documents (matrices, big operators, ...) are converted but less tested.
  • Speed: reading a line is dominated by NVDA's own Word code. Closing the MathType startup template and other Word COM add-ins makes Word noticeably faster.

Troubleshooting

Set the NVDA log level to Debug and look for lines starting with "mathTypeWord" in the log.
